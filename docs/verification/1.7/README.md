# Verification, RimWorld 1.7.5014

Every scenario of this mod was run in the real game on RimWorld 1.7 (`Version.txt`: 1.7.5014 rev1195) on 2026-11-20, through the shared scenario runner (a git submodule of the development repository, not part of this tree). Headless runs used `scripts/run-scenarios` and `scripts/run-all`; windowed runs used `scripts/run-scenarios --windowed --game-env WAYLAND_DISPLAY=wayland-0 --save-screenshots docs/verification/1.7 -s <name>` on a 3840x2160 window with the game's own renderer. Each full image is scaled to 1152 pixels wide by the runner. Every screenshot scenario asserts what the game drew (letter label, letter text, message text, pawns of the group on screen, trees on screen) before the image is kept. Pawn and faction names are the game's generated names; the game window is captured, not the desktop.

## Known limits

- RimWorld 1.7.5014 only in this folder; the results on 1.6.4871 are in `docs/verification/1.6`. The 1.6 failures are filed too: #12 (Factional War combination) and #13 (DLC wall-clock budgets).
- Flaky scenarios, counted with the final code on 1.7.5014 (no scenario was weakened to pass):
  - `dlc-ideology-all-four-incidents-run`: 5 of 7. One failure: "the group of Ideology/CannibalPirate SrPoaching should leave the map; still on the map: Egan at (48, 0, 58) duty=none; lords: " (a pawn left on the map with no lord and no duty). One failure: "Ideology: the crew should fell a tree" with the logging crew already gone.
  - `dlc-royalty-all-four-incidents-run`: 5 of 6. The failure: "Royalty: the crew should fell a tree" with every pawn of the crew gone but one, which still had the job CutPlant and the duty SrTakeWoodExit although its Plants skill was disabled (plant work speed 0.1).
  - `work-settings-incident-pawns-have-initialized-work-settings`: 2 of 3 with its first contrast. The failure was in the scenario's own contrast check ("expected <> but was <Rynyk, Aristi, Virgil>": the vanilla raiders it generated had initialized work settings, so the check that tells the mod's pawns from vanilla ones had nothing to contrast against). Cause found: the game's raid generator redresses pawns from the world pawn pool, and the pawns an earlier incident of this mod had initialized and then sent away are in that pool (shown by seeding the pool with initialized pawns, which the generator then reused). The contrast now generates four pirates with `forceGenerateNewPawn`, which never takes a pool pawn: pass in 5 of 5 launches on 1.7.5014, each launch with the caravan, traveler, poaching, logging and work-settings scenarios.
  - `together-with-factional-war-...`: 2 of 3, the failure is a vanilla error (next point).
  Filed on the project's issue tracker (the numbers are the development tracker's and each is described here), none fixed yet:
  - #9: a poacher left on the map with no lord and no duty (`dlc-ideology-all-four-incidents-run`, 1 of 7).
  - #10: a logging crew member with Plants disabled given tree work, or the crew leaving with no tree felled (`dlc-ideology-all-four-incidents-run` 1 of 7, `dlc-royalty-all-four-incidents-run` 1 of 6).
  - #11: the contrast precondition of `work-settings-incident-pawns-have-initialized-work-settings` failed on some random raiders (1 of 3); a flaw in the scenario, not in the mod. Fixed (see above).
- Plants skill: the logging screenshot scenario, like `logging-hostile-crew-fells-trees-and-leaves` and the logging step of the DLC scenarios, sets the Plants skill of the crew pawns that can use it to 12 so that the crew fells a tree. That differs from random raiders, whose crews sometimes fell none (#10).
- Vanilla log errors (a vanilla bug, not a mod defect). The runner fails a scenario on any `Log.Error`. One was seen: `No shuffled Adulthood found for hunter of TribeSavage. Choosing random.`, logged by `RimWorld.PawnBioAndNameGenerator.FillBackstorySlotShuffled` while Factional War's incident generated a pawn group (`SR.ModRimWorld.FactionalWar.IncidentWorkerFactionWar.TryExecuteWorker` called from the Factional War half of the combination scenario). The attribution was made by reading the stack in the run's `Player.log` by hand; the combination scenario does not check frames. It was told apart by its stack: only `Verse`, `RimWorld` and Factional War frames above the scenario, no frame of `SR.ModRimWorld.RaidExtension`. It is the same family as the one the caravan scenario names (the vanilla error for a trader of TribeSavage in about 1 of 400 generations); the scenarios that choose factions leave TribeSavage out for that reason. Every other run was free of error lines in `Player.log`. No other vanilla error was seen in this pass; the runner has no expected-error list, so a vanilla error fails a run.
- The runner limits apply here: the shared scenario runner's known limits (an expected-error list is missing, and windowed launches on Wayland need the display variable passed). Every windowed launch above needed `--game-env WAYLAND_DISPLAY=wayland-0`, and the one vanilla failure above counts as a failed run. The click helper is 1.7 only, and this folder uses no click.
- The caravan half of the Odyssey fix (the traders guild never sends a hostile caravan) was not observed in the game as an arrival: `odyssey-traders-guild-does-not-walk-in-as-hostile-travelers` observes the traveler half and asserts that the guild has no Trader group, so the caravan half rests on that and on reading the code.
- A scenario of a traveler group sized by game points was dropped in an earlier ticket; the traveler scenarios use 1500 points.
- Anomaly and Salvagers factions are hidden by the game, so the incidents never pick them; the faction-choice scenarios check this by faction list, nothing on screen shows it. The Empire's caravan needs a colonist with a trading permit and is checked as a refusal only.
- `poaching-in-progress` shows the poachers still walking toward the living animal, not the kill; the hostile traveler has no letter, so its shot is the message. The black band in `hostile-traveler-in-progress` is the edge of the 100x100 test map. Some shots are dark because the scenario's map is at night.
- CI runs no scenario (they need the game). It builds both versions, runs the unit tests, the package check and, in the separate `identity` job, `scripts/test-identity`. The job's `apt-get` and tag-fetch steps have been run in the SDK image locally but not yet on the CI runner; the first PR run will show; `scripts/test-translations` needs the game and is not in CI.
