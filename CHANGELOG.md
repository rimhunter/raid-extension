# Changelog

This is a modified version of "Raid Extension" by Shadowrabbit (Shadowrabbit/RaidExtension, last commit 5f91103 "v1.4 support", 2022-10-22, tagged `original-1.4` in this repository), under the Apache License, Version 2.0. This file lists every change from that commit, with its date. Original copyright and license: see LICENSE, NOTICE and MODIFICATIONS.

The continuation is built from Shadowrabbit's own source. No DLL of any build was used. Fixes taken from llunak's 1.6 fork are listed below with the author named.

Add each new change under "Unreleased" with its date as `- YYYY-MM-DD: what changed`. At release, rename the heading to the version and release date.

## Unreleased

## 1.1.0 (2026-11-20)

- 2026-11-20: builds for RimWorld 1.6 and 1.7 from one source, into the `1.6` and `1.7` load folders, selected by `LoadFolders.xml`; `About/About.xml` supports 1.6 and 1.7 (the original supported 1.2, 1.3 and 1.4). The mod references only the game, through the Krafs.Rimworld.Ref package (1.6.4871 for 1.6, 1.7.5014-unstable for 1.7). It uses no Harmony and no other library, as the original.
- 2026-11-20: the per-version folders `1.2`, `1.3` and `1.4` are gone; the 1.4 source is the base (`Source/`), and `Defs` and `Languages` stay at the root. The prebuilt `Assemblies/ModRimWorldRaidExtension.dll` files, the bundled game libraries `Lib/Assembly-CSharp.dll` and `Lib/UnityEngine.CoreModule.dll`, the old project and solution files and `Properties/AssemblyInfo.cs` (the SDK generates it) are not committed.
- 2026-11-20: compile fix taken from llunak's 1.6 fork, commit 7ae3fe2 (2025-06-12, "make build with 1.6"): `FactionCanBeGroupSource` in `IncidentWorkerPoaching`, `IncidentWorkerLogging`, `IncidentWorkerHostileTraveler` and `IncidentWorkerHostileTraderCaravanPassing` overrides the new public `(Faction, IncidentParms, bool)` signature and takes the map from `parms.target`, and the two `CandidateFactions` calls take `parms`. Re-checked against the 1.6.4871 and 1.7.5014 game libraries.
- 2026-11-20: compile fix, `JobGiverAIFightAnimal`: `MeleeAttackJob(pawn, enemyTarget)` takes the pawn, as llunak's 1.6 fork does since commit 45bce64 (2024-09-30, "port 1.5 changes from Ionfrigate12345/Rimworld_RaidExtensionContinued"). Re-checked against the 1.6.4871 and 1.7.5014 game libraries.
- 2026-11-20: compile fix by rimhunter, not taken from another build: `JobGiverAIFightAnimal` calls `enemyTarget.IsPsychologicallyInvisible()` in place of the removed `Pawn.IsInvisible()`. This is the game's own check on the target (`JobGiver_AIFightEnemy`). The fork's call at commit 45bce64 checks the poacher instead of the target, so it was not used.
- 2026-11-20: removed `About/PublishedFileId.txt`, which held the original's Workshop item id (2554928098). This mod's Workshop id is recorded when it is first uploaded; `scripts/package` refuses to package while the file is in the tree.
- 2026-11-20: removed `Languages/Korean/LanguageInfo.xml`. It is language metadata, not mod text: the game reads the first `LanguageInfo.xml` found for a language folder named `Korean`, so it could replace the game's own. The Korean translation files are kept unchanged.
- 2026-11-20: `About/About.xml` is the identity needed for the mod to load: name "Raid Extension (rimhunter)", packageId `rimhunter.raidextension` (the original's was `SR.ModRimworld.RaidExtension`), version 1.1.0, `supportedVersions` 1.6 and 1.7, `loadAfter` `Ludeon.RimWorld` and `Ludeon.RimWorld.Royalty`, and `incompatibleWith` for `sr.modrimworld.raidextension` and `sr.modrimworld.raidextensioncontinued`. The description text corrects "hositle" to "hostile".
- 2026-11-20: new `NOTICE`, `MODIFICATIONS`, `CONTRIBUTING.md` and this changelog. `LICENSE` is the original file, unchanged.
- 2026-11-20: `scripts/package` writes `dist/rimhunter.raidextension` and ships `NOTICE`, `MODIFICATIONS`, `CHANGELOG.md` and the folders for each game version with `Source/`; it never ships the test runner, the tests or a `PublishedFileId.txt`.
- 2026-11-20: `About/About.xml` gains the `<url>` `https://github.com/rimhunter/raid-extension`, the author line "Shadowrabbit, llunak, rimhunter" (the compile fixes above are taken from llunak's fork), and a description that says this is a continuation, credits Shadowrabbit and llunak, states rimhunter claims no ownership, takes no donations and names the build to disable.
- 2026-11-20: `About/Preview.png` is replaced by a new image drawn by rimhunter with `scripts/make-art`. The original's preview was made by another artist who published no license; no image of the original is in this repository's tree.
- 2026-11-20: new `Readme.md` and `WORKSHOP.md` (the Steam BBCode page text, which states no Workshop id for this mod), neither packaged. New `docs/verification/1.7/01-mod-list-incompatibility-warning.png`.
- 2026-11-20: new in-game scenarios and stand-in mods for the mod list warning (in the test-only companion folder, never packaged), and new checks in `scripts/test-identity`.
- 2026-11-20: Poaching and Logging no longer write a warning to the log each time the storyteller checks whether they can fire (no large animal, no tree), and Poaching no longer writes "signal don't care" for every lord signal that is not a tick. The original logged a warning in each case (`IncidentWorkerPoaching`, `IncidentWorkerLogging`, `TriggerTargetAnimalDead`). llunak's 1.6 fork removed the second one by deleting the trigger (commit 1d57e3a); this change keeps the trigger and drops the log line, not taking his code.
- 2026-11-20: the hostile traveler ("Lost Raider") and the hostile trader caravan again apply the game's own rules for a faction that arrives on foot: `arrivalLayerWhitelist`, `arrivalLayerBlacklist`, `onlyAllowWhitelistedArrivals`, and the faction's `arrivalModeWhitelist` and `arrivalModeBlacklist` as the game's `EdgeWalkIn` arrival mode checks them (`HostileVisitorFactions.MayWalkInOn`). The original replaced the game's `FactionCanBeGroupSource` without those checks, which on 1.7 with Odyssey let the hostile traders guild (arrival modes: drops only) walk in on foot as "Lost Raiders". This fix, by rimhunter, is observed for the traveler only; the guild has no Trader group, so the caravan half has no scenario. New in-game scenarios cover both incidents.
- 2026-11-20: new in-game scenario `together-with-factional-war-both-load-and-an-incident-of-each-runs-with-no-errors` (test-only, never packaged): Raid Extension and Factional War (rimhunter) 1.1.0 or later, built from Factional War's `origin/main` (first run: commit 08f708b, 1.1.0), load in one mod list and share no def, defName, type or keyed key. A Poaching incident, then a Faction Assault incident, each run to their end with their letters and no log error; the battle ends only when one side has no standing pawn on the map and one of its pawns is dead or downed, and the game's end message is shown. It needed no change to the mod. `scripts/prepare-factional-war` builds the Factional War copy the scenario loads (a git-ignored folder in the repository, kept out of the staged mods). Not observed: the two incidents run one after the other, not at once; only those two of the eight incidents run; 1.7.5014 with Core only, not 1.6 or a DLC; Factional War is built against its own Krafs pin (1.7.5011-unstable).
- 2026-11-20: new in-game scenarios by rimhunter run all four incidents (Poaching, Logging, the hostile caravan and the hostile traveler) with Royalty, Anomaly, Biotech, Ideology and Odyssey each loaded alone, and with all five together, on 1.7.5014, and run them again with each hostile faction those DLC add that can send them (Royalty: the Empire; Biotech: the neanderthal and impid tribes, the pig outlanders, and the yttakin and waster pirates, whose pawns are of the faction's xenotype; Ideology: the cannibal and nudist tribes and the cannibal pirates). Each incident fires, shows its letter or message, reaches its end, and the log holds no error. Not observed: Anomaly (its factions are hidden, so no incident can pick them), the Empire's caravan (it needs a colonist with the trading permit, as the game's own caravan does; the scenario checks it is refused without one), 1.6, a DLC the install does not own.
- 2026-11-20: by rimhunter: Poaching and Logging only pick a faction that can walk in (`HostileVisitorFactions.MayWalkInOn`, as the traveler and caravan do since the Odyssey fix above), and generate only humanlike pawns by filtering the pawn options (`CanUsePawnGenOption`) instead of rejecting each generated pawn (`CanUsePawn`). With Odyssey the hostile traders guild (arrival modes: drops only) could be picked and logged "Could not resolve arrival mode for raid"; with Biotech, factions whose pawn options include animals logged "Could not generate a pawn after 100 tries ... Ignoring validator". For the humanlike filter the approach is llunak's (llunak's commit 56db981, https://github.com/llunak/rimworld-RaidExtension/commit/56db981); this implementation is written separately from the game's API, by rimhunter.
- 2026-11-20: by rimhunter, not taken from another build: the poachers leave when their target animal has left the map alive (a fleeing animal can walk off the edge). The target was only checked for being dead or missing, so the group stayed on the map for good; now a target that is no longer on the map is replaced by another animal in reach, or the group leaves, and only an animal on the map counts as a target. An in-game scenario despawns the animal during the hunt. Known limit: when the group leaves with no prey, the message still reads "ready to leave with the prey" (no new translation keys).
- 2026-11-20: by rimhunter, not taken from another build: the pawns that Poaching, Logging, the hostile caravan and the hostile traveler create now have initialized work settings (the game's own `Pawn_WorkSettings.EnableAndInitializeIfNotAlreadyInitialized`, as the game does for siege raiders in `LordToil_Siege`), set where each incident's worker creates them. The game sets work priorities only for player pawns, so another mod's patch that calls `Pawn_WorkSettings.WorkIsActive` on a raider (the loggers ask the game's tree-lover check, `PlantUtility.PawnWillingToCutPlant_Job`, for each raider) logged "<pawn> did not have work settings initialized." once per pawn; a test patch did this for 14 pawns of one Logging crew. Raiders still run their duties, not colony work: a colonist takes a hauling job from the same stockpile in the scenario, initialized hostile pawns with the Defend duty do not, and the incident pawns take only the jobs their duties give. Observed with new scenarios (they fail before the change and pass after); not observed: the other mod's own patch, 1.6.
- 2026-11-20: by rimhunter: translations audited. Every text the code shows a player (the two leave messages, the hostile caravan letter, the Poaching and Logging letters) already came from a translation key or a def field with a `DefInjected` entry, so no English text moved out of the code and no translation key was added; a new unit test (`DrawnTextCheck`) fails the build when an English literal is passed to a letter, message or other drawing call, and when a def text has no English `DefInjected` entry. A non-English player would see English for any key added later until a translator adds it; there is none today. All nine language folders of the original keep every key and text (Chinese Simplified and Traditional, English, French, German, Japanese, Korean, Portuguese Brazilian, Russian). New in-game scenarios check the English text the running game draws (the typo fix below included), load each of the nine and boot the game in each of the eight non-English languages, and check that the letters, labels, report string and keys show the text of that language's own files (`scripts/test-translations`).
- 2026-11-20: by rimhunter: the original's English spelling "Hositle" is corrected to "Hostile" in the English text of the hostile caravan: the letter title "Hositle faction caravan passing by" (key `SrHostileTraderCaravanPassing`) and the incident label "Hositle Caravan Passing By" (`SrHositleCaravanPassing.label`, also in `Defs`). Only English text changes: every key and every def name, including the `Hositle` in `SrHositleCaravanPassing` and `SrHositleTraveler`, stays as the original has it, and no other language's text changes. `scripts/test-identity` lists the two corrected English texts as the only allowed difference from the original's translations.
- 2026-11-20: by rimhunter: new `scripts/publish-github`, which publishes a merged release commit to the public GitHub repository with the noreply author and checks every file against the source commit; it touches GitHub only with `--publish`, and `--dry-run` prints the plan.
- 2026-11-20: by rimhunter: the hostile traveler ("Lost Raider") sends a message and no letter, as the original does; a letter appears only when an arriving pawn has a relation with a colonist, and then it is the game's own letter. The in-game scenario and the screenshot `hostile-traveler-message-on-arrival` show the message.
- 2026-11-20: by rimhunter: the work settings of the incident pawns are initialized for humanlike pawns only; a humanlike pawn without a work settings object throws an error naming the pawn, so the only pawns skipped are animals. `JobGiverAIFightAnimal` uses the shared `MiscDef.MinTargetRequireHealthScale` constant in place of its own copy of the same value (1.2).
- 2026-11-20: by rimhunter: new `docs/verification/1.6/README.md` and `docs/verification/1.7/README.md` list every in-game scenario run on each game version with its result, the known limits and the screenshots of each incident's letter, message and group (`docs/verification/<version>/*.png`); none of it is packaged.
